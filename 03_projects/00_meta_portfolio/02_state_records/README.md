# 변화 기록

프로젝트 진행 과정에서 발생한 주요 변화와 실험을 기록한다.
- exp (Experiment): 어떤 실험이 수행되었는가
- rfl (Reflection): 모델이 어떻게 변했는가
- def (Definition): 핵심 개념이 어떻게 재정의되었는가
- evo (Evolution): 프로젝트 관점이 어떻게 진화했는가

> exp → rfl → def → evo

결과물보다 프로젝트가 어떻게 변화했는지를 추적하기 위한 공간이다.

---

## Types

### exp
지표 및 모델 실험

- 파라미터 튜닝
- 계산식 검증

### rfl
프로젝트 내부 객체에 대한 해석 변화

- PUL 재해석
- QCI 의미 수정

### def
핵심 개념의 정의 변화

- 포트폴리오 정의 변화
- 데이터분석가 역할 재정의

### evo
프로젝트 관점 및 문제 구조의 변화

- 측정 대상 재정의
- 관측 단위 설계
- 분석 관점 변화

## Record Structure

프로젝트 진행 과정에서 기록 방식 또한 설계의 대상이 되었다.  
변화 기록은 다음 구조를 기본 형식으로 사용한다.

- Context: 변화가 발생하기 전의 문제 상황 또는 이전 상태
- Shift: 기존 관점에서 무엇이 변경되었는가
- Implication: 해당 변화가 모델, 프로젝트 또는 해석 프레임에 미치는 영향
- Notes: 관련 메모, 예시, 후속 질문 또는 기록 형식에 대한 메타 메모

### Recording Principle

이 구조는 결과물의 완성도를 기록하기 위한 것이 아니라,
프로젝트 내부에서 발생한 변화 이벤트를 기록하기 위한 구조이다.

따라서 각 문서는 무엇을 주장하는가보다

- 어떤 상태에서 시작했는가
- 무엇이 변화했는가
- 그 변화가 무엇을 바꾸었는가

를 중심으로 작성한다.

### Historical Records

2026-06-18 이전 기록은 현재 형식이 정립되기 전 작성된 문서로,
당시의 사고 구조와 기록 방식을 그대로 보존한다.

따라서 과거 문서와 이후 문서는 형식이 다를 수 있으며,
이 차이 또한 프로젝트 진화 과정의 일부로 간주한다.

## Versioning

프로젝트 버전은 개별 기록에 부여되지 않는다.

버전은 특정 시점에 프로젝트의 문제 정의,
분석 대상 또는 해석 프레임이 변화했을 때
여러 state record를 종합하여 부여하는 마일스톤이다.

즉,

- state_record = 변화 이벤트
- version = 변화 이벤트들의 해석 결과

로 구분한다.

예시:

- v1 : 포트폴리오 이해도 측정 중심
- v2 : 포트폴리오 개념 재정의 과정 관찰 중심

## 기억에 남는 내용

### 검증 설계

QA는 문제를 발견하는 과정인 동시에, 무엇을 검증해야 하는지를 구조화하는 과정이라는 점이 흥미로웠다.

- 문제가 발생할 수 있는 조건을 충분히 정의할 수 있다면, 일부 검증 과정은 자동화할 수도 있겠다는 생각이 들었다.

### 조직 관점

기능을 검증할 때 영업, 마케팅, CS 등 다양한 부서의 관점을 반영하는 것이 중요하다는 점이 인상적이었다.

- 업무 역시 현재 단계만 보는 것이 아니라, 다음 단계에서 어떻게 활용될지까지 함께 고려해야겠다는 생각이 들었다.
- 결국 조직은 하나의 워크플로우이고, 내 업무의 Output은 다음 업무의 Input이 된다.

## 느낀 점

- 당연한 내용들을 차근차근 따라가다 보면, 미처 생각하지 못했던 결론에 도달하게 되는 설명 방식이 인상적이었다.
  - 목표는 정의에서 비롯되고, 정의는 곧 범위를 제한하는 일이라는 점을 새삼 깨닫게 되었다.
  - 무엇을 포함할지 정하는 순간, 무엇이 제외될지도 함께 결정된다.

## 데이터 분석 관점의 확장

프로젝트 흐름은 보통 아래와 같다.

> 설계 -> 개발 -> QA -> 운영 -> 개선

QA를 학습하면서 데이터 분석 관점으로 사고를 확장해볼 수 있었다.

- 설계: 측정/지표 설계
- 개발: 이벤트/로그 설계
- QA: 로그 기반 검증
- 운영: 사용 데이터 확인
- 개선: 데이터 기반 의사결정

## 요약

- RDBMS의 R은 `ERD의 관계`가 아니라, `집합론에서의 Relation`을 의미한다.
  - Relation은 카테시안 곱의 부분집합이다.
  - SQL에서 테이블은 중복을 허용하는 multiset 구조로 동작하지만,  
    관계대수와 최적화 단계에서는 이를 Relation(set 기반 구조)으로 해석하여 연산을 정의한다.

- 핵심 연산 해석:
  - WHERE: 조건을 기준으로 공간 절단
  - SELECT: 전체 속성 중 일부 열만 선택
  - JOIN: 카테시안 곱 결과에서 공통 속성 조건을 만족하는 튜플만 선택하여 결합

- 이 과정에서 중요한 성질은 닫힘성(R → R)이다.
  - 모든 연산 결과가 다시 릴레이션으로 유지되기 때문에 연산을 체이닝할 수 있다.

- 실행 계획은 이러한 관계대수 구조를 기반으로 재배열되며,  
  옵티마이저는 비용 기반으로 최적의 실행 경로를 선택한다.

## 서평

- 쿼리 실행순서, 서브쿼리와 뷰, 정규화 등 외워졌던 것들의 의미를 알게 되었다.
- SQL 구문이 각각 독립된 기능이 아니라 관계대수 기반의 연산 구조로 연결되어 있다는 점을 이해하게 되었다.
- 이를 통해 데이터 처리 구조를 하나의 흐름으로 바라볼 수 있게 되었다.

# [치킨 쿠폰](https://school.programmers.co.kr/learn/courses/30/lessons/120884)

## 문제

치킨을 주문하면 치킨 1마리 당 쿠폰 1장을 받는다.  
쿠폰 10장을 모으면 서비스 치킨 1마리를 받을 수 있고, 서비스 치킨을 받아도 쿠폰 1장이 다시 발급된다.

주문한 치킨 수 `chicken`이 주어질 때, 받을 수 있는 최대 서비스 치킨 수를 반환한다.

---

## 예시

```python
chicken = 39
```

처음 쿠폰은 39장이다.

```text
쿠폰 39장 → 서비스 치킨 3마리
```

서비스 치킨으로 쿠폰 3장이 다시 생겨, 쿠폰은 총 12장이 된다.

```text
쿠폰 12장 → 서비스 치킨 1마리
```

따라서 받을 수 있는 총 서비스 치킨 수는 `3 + 1 = 4` 이다.

---

## 접근

가지고 있는 쿠폰과 누적된 서비스 치킨 수를 상태로 관리하면서,  
쿠폰으로 받을 수 있는 서비스 치킨 주문을 반복한다.

---

## 코드

```python
def calculate_service_chicken(chicken):
    coupons = chicken
    total_service_chicken = 0

    while coupons >= 10:
        earned_service_chicken = coupons // 10

        total_service_chicken += earned_service_chicken
        coupons = coupons % 10 + earned_service_chicken

    return total_service_chicken
```

---

## 정리

### 구현

이 문제는 머릿속으로 이해한 과정을 코드로 변환하는 과정이 어려웠다.  

특히 반복 과정에서 어떤 값을 저장하고 어떤 순서로 갱신해야 하는지 정하는 과정이 필요했다.  
먼저 `coupons`와 `total_service_chicken`을 기준으로 반복 구조를 구현했다.

```python
while coupon >= 10:
    total_service_chicken += coupons // 10
    coupons = coupons % 10 + coupons // 10
```

이후 코드를 다시 확인하는 과정에서 `coupon // 10` 이라는 동일한 계산이 반복되고 있다는 것을 발견했다.  
이를 하나의 변수로 분리하여 `earned_service_chicken`으로 표현하면서 코드를 개선했다.

```python
while coupons >= 10:
    earned_service_chicken = coupons // 10

    total_service_chicken += earned_service_chicken
    coupons = coupons % 10 + earned_service_chicken
```

중간 계산값을 변수로 분리하니 반복 과정에서 어떤 값을 계산하고 갱신하는지 더 명확하게 표현할 수 있었다.

### 설계

그렇다면 나는, 처음부터 중간 변수를 설계한 사람과 어떤 사고 과정의 차이가 있었을까?  

차이는 문제를 바라보는 관점에 있었을 것이다.  
나도 `현재 쿠폰`과 `총 서비스 치킨`이라는 상태는 정의했지만,  
반복 과정에서 발생하는 중간 결과까지 별도의 상태로 표현하지는 않았다.

반면 처음부터 중간 변수를 설계한 사람은,

```text
현재 쿠폰  
↓  
이번 반복에서 얻는 서비스 치킨  
↓  
다음 쿠폰 상태
```

처럼 상태 변화 과정 자체를 모델링하고, 반복 과정에서 생성되는 값을 변수로 표현했을 것이다.  
즉 단순히 현재 값을 관리하는 것을 넘어, 상태가 어떻게 변화하는지까지 표현하는 것이 변수 설계로 이어진 것이다.

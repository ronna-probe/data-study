# 프로젝트 전달 전략

본 문서는 메타 포트폴리오 프로젝트를 외부에 설명하고 전달하기 위한 원칙을 정의한다.

본 프로젝트는 결과물 자체보다 질문, 상태 변화, 개념 재정의 과정을 관찰하는 것을 목표로 한다.  
따라서 프로젝트 전달 또한 결과 중심이 아니라 변화 과정 중심으로 구성한다.

---

## Communication Principle

프로젝트는 다음 구조를 중심으로 설명한다.

```text
Question
↓
State Change
↓
Definition Transition
↓
Decision
```

즉,

> 무엇을 만들었는가

보다

> 어떤 질문이 어떤 상태 변화를 만들었는가

를 중심으로 전달한다.

---

## Presentation Structure

프로젝트는 다음 순서로 설명한다.

```text
Project Context
↓
Question Log
↓
State Record
↓
Definition Transition
↓
Current Interpretation
```

이를 통해 특정 결과가 아니라,  
결과에 도달하게 된 과정을 함께 전달한다.

---

## Question Evolution

질문은 프로젝트의 핵심 관찰 단위이다.

동일한 주제에 대해서도 질문의 형태는 지속적으로 변화할 수 있다.

예시

```text
포트폴리오란 무엇인가?
↓
무엇을 측정해야 하는가?
↓
무엇을 관측 단위로 볼 것인가?
↓
정의는 발견되는가, 만들어지는가?
```

질문의 변화는 개념 변화의 신호로 해석한다.

---

## Representative Cases

모든 로그를 설명하지 않는다.

대신 의미 있는 상태 전이를 보여주는 대표 사례를 선택한다.

```text
Question
↓
GPT Response
↓
Reframe
↓
State Change
↓
Apply
```

이를 통해 질문이 실제 의사결정으로 이어지는 과정을 보여준다.

---

## State Snapshot

```text
Output은 최종 결과물이 아니라 특정 시점의 상태 해석이다.

Question Log
↓
State Record
↓
State Snapshot
```

따라서 State Snapshots은 정답이 아니라 해당 시점의 해석 결과로 간주한다.

---

## Summary

본 프로젝트의 전달 목표는 결과를 설명하는 것이 아니라,

- 질문의 변화
- 상태의 변화
- 개념의 재정의
- 의사결정의 형성

과정을 보여주는 것이다.

따라서 프로젝트는 결과 중심이 아닌 전이(Transition) 중심으로 설명한다.

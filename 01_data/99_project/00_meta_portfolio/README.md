# 🧠 Data Analyst Portfolio Learning Experiment  
## Modeling how the concept of a portfolio is formed through behavioral data logging with GPT

본 프로젝트의 목적은
GPT와의 대화 과정에서 나타나는 인지적 변화(cognitive transition)를
행동 데이터로 모델링하는 것이다.

---

## 0. 모델 정의

본 프로젝트는 질문 기반 사고를 상태로 모델링하고,
이를 지표로 추적하는 시스템이다.

---

## 1. 문제 정의

'데이터 분석 포트폴리오'가 무엇인지 명확히 이해하지 못한 상태에서 시작하게 되었다.

좋은 포트폴리오의 기준은 무엇인지 등을 알아보고자 했지만, 대부분의 정보는 결과물 중심으로 설명되어 있었다.
이에 결과물이 아닌 형성 과정에 주목하였다.

일반적인 데이터 분석 포트폴리오가 데이터를 활용해 특정 문제를 해결하는 데 초점을 둔다면,
본 프로젝트는 '포트폴리오라는 개념이 질문과 의사결정 과정을 통해 어떻게 재정의되는가'를 분석 대상으로 삼는다.

즉, 분석 대상은 개별 질문이나 로그가 아니라,
각 시점에서 정의되는 "포트폴리오의 개념 상태(state of definition)"이며,
시간에 따라 이 상태가 어떻게 전이(transition)되는지를 관측한다.

본 프로젝트는 비정형 질문 로그를 기반으로
개념이 생성 → 수정 → 재구성되는 과정을 추적하며,
그 결과로 나타나는 "정의의 변화 구조"를 분석하는 프로젝트이다.

이러한 의미에서 본 프로젝트는 '포트폴리오에 대한 포트폴리오',
즉 하나의 메타 포트폴리오(meta-portfolio)라고 할 수 있다.

따라서 프로젝트명은 `00_meta_portfolio`로 정의하였다.

---

## 2. 분석 설계

본 프로젝트는 포트폴리오 개념을 중심으로  
이해 및 의사결정 과정을 **이벤트 기반 데이터 구조(event-based logging)**로 변환하여 분석한다.

### 2.1 데이터 수집 (Airtable Logging)

본 프로젝트의 데이터는 GPT와의 상호작용 과정에서 생성되며,
각 상호작용은 하나의 이벤트 단위로 기록된다.

본 프로젝트의 원천 데이터는 Airtable에서 관리하며,
질문 로그는 프로젝트 진행 과정에서 지속적으로 추가된다.
따라서 현재 저장소에는 데이터셋 원본은 포함하지 않는다.

### 2.2 데이터 한계

본 프로젝트의 데이터는 개인이 직접 기록한 데이터로,
해석과 판단 과정에서 주관성이 개입될 수 있다.

동일한 질문과 응답이라도 기록 시점에 따라 다른 의미로 해석될 수 있으며,
상태 변화와 의사결정 또한 객관적 측정값이 아닌 개인의 판단을 포함한다.

따라서 본 데이터는 절대적인 사실을 측정하기보다,
특정 시점의 인식과 의사결정 과정을 관측하기 위한 데이터로 해석한다.

### 2.3 분석 구조

본 프로젝트는 KPI 중심 분석이 아니라 다음 구조를 따른다:

- 질문 발생
- 개념 정의 생성
- 정의 수정
- 정의 재구성
- 새로운 정의 도달

이를 통해 다음을 분석한다:

- 어떤 질문이 개념 변화를 유발하는가
- 정의는 어떤 조건에서 재구성되는가
- 개념 변화는 누적형인가 / 비선형인가

---

## 3. 프로젝트 구조

본 프로젝트는 질문 로그, 상태 변화 기록, 설계 문서를 분리하여 관리한다.

### archive

프로젝트 진행 과정에서 사용되었던
이전 버전의 설계, 정의, 결과물을 보관한다.

현재 분석 체계에는 포함되지 않지만,
프로젝트의 변화 과정을 추적하기 위한 기록으로 유지한다.

### docs

프로젝트의 분석 관점, 가설, 데이터 구조 등
분석 프레임워크를 정의하는 문서들을 관리한다.

### state_records

프로젝트 진행 과정에서 발생한
상태 변화(State Transition)를 기록한다.

각 기록은 특정 질문 또는 의사결정을 통해
개념 정의가 어떻게 변화했는지를 담고 있다.

### state_snapshots

특정 시점에서의 프로젝트 상태를 요약한 문서이다.

State Record를 기반으로 현재 정의와 해석을 정리하며,
프로젝트의 상태 스냅샷 역할을 수행한다.

---

## 4. 가설

본 프로젝트에서 탐색하고자 하는 가설은 다음과 같다.

### H1

질문 및 의사결정 이벤트의 밀도가 높을수록,
포트폴리오 개념 상태(state of definition)의 전이(transition) 빈도는 증가할 것이다.

### H2

단순한 다음 단계 선택(continuation)보다,
개념 정의를 실제로 수정하거나 재구성하는 이벤트는
더 높은 인지적 비용(추론 깊이, 질문 반복, 맥락 확장)을 수반할 것이다.

### H3

개념에 대한 이해는 누적형 학습이라기보다,
기존 정의를 반복적으로 재해석하고 재구성하는 비선형적 구조를 따른다.

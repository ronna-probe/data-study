# 프로젝트 운영 전략

Date: 2026-06-17

본 문서는 메타 포트폴리오 프로젝트의 운영 원칙과 진행 방식을 정의한다.

본 프로젝트는 고정된 데이터셋을 분석하는 프로젝트가 아니라,  
질문과 상태 변화가 지속적으로 축적되는 관찰 시스템이다.

따라서 운영의 목적은 결과물을 빠르게 생산하는 것이 아니라,  
상태 변화와 개념 재정의 과정을 안정적으로 기록하고 관리하는 데 있다.

---

## Operation Principle

프로젝트는 다음 순서로 운영한다.

```text
Question Log
    ↓
State Record
    ↓
Interpretation
    ↓
State Snapshot
```

새로운 질문이 발생하면 로그로 기록하고,  
의미 있는 변화가 발생한 경우 State Record로 정리한다.

State Snapshot은 이러한 기록을 기반으로 특정 시점의 상태를 해석한 결과물로 생성한다.

---

## Observation First

본 프로젝트는 분석보다 관찰을 우선한다.

초기 단계에서는 지표 설계나 정량화보다

- 무엇이 변화했는가
- 어떤 질문이 발생했는가
- 어떤 정의가 수정되었는가

를 기록하는 데 집중한다.

---

## Incremental Design

데이터 구조와 분석 프레임워크는 고정되지 않는다.

프로젝트 진행 과정에서

- 새로운 관찰 단위 발견
- 새로운 상태 유형 발견
- 새로운 가설 생성

이 발생할 수 있으며,  
구조는 이에 따라 점진적으로 수정한다.

---

## Documentation Strategy

의미 있는 변화는 문서로 기록한다.

Docs는 프로젝트의 현재 정의를 기록하고,

State Records는 실제 변화 과정을 기록한다.

따라서

- Docs = 설계 문서
- State Records = 관찰 기록

으로 역할을 구분한다.

---

## Version Management

프로젝트 정의가 크게 변경되는 경우  
새로운 버전으로 관리한다.

기존 설계는 삭제하지 않고 보관하며,

- v1
- v2
- v3

형태로 변화 과정을 추적할 수 있도록 유지한다.

과거 설계와 가설은 Archive에 보관한다.

---

## Summary

본 프로젝트의 운영 목표는

- 질문 로그 축적
- 상태 변화 기록
- 개념 재정의 추적
- 결과물 버전 관리

를 지속적으로 수행하는 것이다.

따라서 프로젝트 운영의 핵심은 분석 수행 자체가 아니라,  
변화 과정을 안정적으로 관찰하고 기록할 수 있는 시스템을 유지하는 데 있다.

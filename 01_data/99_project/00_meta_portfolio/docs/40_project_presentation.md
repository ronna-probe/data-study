# 프로젝트 전달 전략

Date: 2026-06-17

본 프로젝트는 일반적인 데이터 분석 프로젝트와 다른 특성을 가진다.

대부분의 분석 프로젝트는 고정된 데이터셋을 기반으로  
지표를 계산하고 결과를 도출하는 것을 목표로 한다.

반면 본 프로젝트는 질문 로그를 통해  
개념이 변화하고 재정의되는 과정을 관찰하는 것을 목표로 한다.

따라서 결과 자체보다

- 어떤 질문이 발생했는가
- 어떤 상태 변화가 발생했는가
- 무엇이 재정의를 유발했는가

를 전달하는 것이 중요하다.

---

## Communication Principle

본 프로젝트는 결과물 중심이 아니라  
변화 과정 중심으로 설명한다.

```text
Question
    ↓
State Change
    ↓
Definition Transition
    ↓
Decision
```

즉,

> 무엇을 만들었는가

보다

> 어떤 질문이 어떤 상태 변화를 만들었는가

를 중심으로 전달한다.

---

## Presentation Structure

프로젝트는 다음 순서로 설명한다.

```text
Project Context
    ↓
Question Log
    ↓
State Record
    ↓
Definition Transition
    ↓
Current Interpretation
```

---

## Question Evolution

질문은 본 프로젝트의 핵심 관찰 단위이다.

동일한 주제에 대해서도  
질문의 형태는 지속적으로 변화할 수 있다.

예시

```text
포트폴리오란 무엇인가?

    ↓

무엇을 측정해야 하는가?

    ↓

무엇을 관측 단위로 볼 것인가?

    ↓

정의는 발견되는가, 만들어지는가?
```

이를 통해 질문 자체가  
개념 변화의 신호로 작동함을 관찰할 수 있다.

---

## State Transition

질문은 상태 변화를 유발하는 이벤트로 간주한다.

프로젝트에서는 개별 질문보다

```text
State A
    ↓
Question
    ↓
State B
```

구조를 중요하게 다룬다.

따라서 분석의 대상은  
정답이나 결과물이 아니라  
상태 전이(State Transition)이다.

---

## Representative Cases

프로젝트에서는 모든 로그를 설명하지 않는다.

대신 의미 있는 상태 변화를 보여주는  
대표 사례를 선택하여 설명한다.

예시

```text
Question
    ↓
GPT Response
    ↓
Reframe
    ↓
State Change
    ↓
Apply
```

이를 통해 질문이 실제 의사결정으로 이어지는 과정을 보여준다.

---

## Outputs

Output은 최종 결과물이 아니라  
특정 시점에서의 상태 해석이다.

```text
Question Log
    ↓
State Record
    ↓
Output
```

따라서 Output은 정답이 아니라  
해당 시점의 해석 결과로 간주한다.

---

## Summary

본 프로젝트는 분석 결과를 보여주는 프로젝트가 아니다.

질문 로그를 기반으로

- 상태 변화가 어떻게 발생하는지
- 개념이 어떻게 재정의되는지
- 의사결정이 어떻게 형성되는지

를 관찰하고 기록하는 프로젝트이다.

따라서 프로젝트 전달의 핵심은 결과보다는  
변화 과정 및전이 구조를 보여주는 데 있다.

# 이 계산 결과를 그대로 믿어도 될까요?

데이터를 필터링하고, 연결하고, 집계하고, 계산하면 하나의 결과가 나온다.

하지만 SQL이나 pandas에서 오류 없이 실행되었다고 해서 그 결과가 항상 올바른 것은 아니다.

계산 과정에서 데이터가 잘못 포함되거나 제외될 수도 있고,  
계산한 값이 질문의 의도와 다를 수도 있다.

따라서 분석이 끝난 뒤에는 결과를 그대로 사용하는 것이 아니라  
**결과가 제대로 만들어졌는지, 의도한 의미를 가지고 있는지 확인하는 과정**이 필요하다.

---

## 질문

> 계산은 정상적으로 끝났는데, 이 결과를 정말 믿어도 될까?

- 계산한 값이 원본 데이터와 맞는가?
- 내가 구하려던 값을 계산한 것이 맞는가?
- 실제 데이터를 몇 개 확인해봐도 결과가 맞는가?

---

## 데이터

주문 데이터를 이용해 고객별 주문 금액을 계산한다고 가정하자.

| order_id | customer_id | amount |
|---:|---:|---:|
| 1 | 101 | 10000 |
| 2 | 102 | 15000 |
| 3 | 101 | 12000 |
| 4 | 103 | 8000 |
| 5 | 102 | 20000 |

---

## 1. 계산한 값이 원본 데이터와 맞는가?

<details>
<summary>⋯</summary>

먼저 고객별 주문 금액을 계산해보자.

### SQL

```sql
SELECT
    customer_id,
    SUM(amount) AS total_amount
FROM orders
GROUP BY customer_id;
```

### pandas

```python
customer_amount = (
    orders
    .groupby("customer_id", as_index=False)["amount"]
    .sum()
    .rename(columns={"amount": "total_amount"})
)

customer_amount
```

결과는 다음과 같다.

| customer_id | total_amount |
|---:|---:|
| 101 | 22000 |
| 102 | 35000 |
| 103 | 8000 |

이 결과가 제대로 계산되었는지 확인하려면  
**집계한 금액의 합과 원본 데이터의 금액 합을 비교**할 수 있다.

### SQL

```sql
SELECT
    SUM(amount) AS total_amount
FROM orders;
```

```sql
SELECT
    SUM(total_amount) AS total_amount
FROM (
    SELECT
        customer_id,
        SUM(amount) AS total_amount
    FROM orders
    GROUP BY customer_id
);
```

### pandas

```python
orders["amount"].sum()
```

```python
customer_amount["total_amount"].sum()
```

두 결과가 모두 `65000`이라면 고객별로 나눈 금액을 다시 합쳤을 때 원본 금액과 일치한다.

이처럼 **계산 전후의 값을 서로 대조하면 계산 과정에서 값이 빠지거나 추가되었는지 확인**할 수 있다.

</details>

---

## 2. 내가 구하려던 값을 계산한 것이 맞는가?

<details>
<summary>⋯</summary>

계산 결과의 숫자가 정확하더라도  
**질문의 의도와 다른 값을 계산했다면 올바른 분석 결과라고 할 수 없다.**

예를 들어 다음과 같은 질문을 받았다고 해보자.

> 고객별 주문 금액은 얼마인가?

이 질문에는 고객별 전체 주문 금액을 계산할 수 있다.

### SQL

```sql
SELECT
    customer_id,
    SUM(amount) AS total_amount
FROM orders
GROUP BY customer_id;
```

### pandas

```python
orders.groupby("customer_id")["amount"].sum()
```

하지만 질문이 다음과 같다면 계산 방법이 달라진다.

> 고객별 주문 한 건의 평균 금액은 얼마인가?

### SQL

```sql
SELECT
    customer_id,
    AVG(amount) AS average_amount
FROM orders
GROUP BY customer_id;
```

### pandas

```python
orders.groupby("customer_id")["amount"].mean()
```

두 계산 모두 문법적으로는 정상적으로 실행된다.

하지만 첫 번째 결과는 **고객별 전체 주문 금액**이고,  
두 번째 결과는 **고객별 주문당 평균 금액**이다.

따라서 결과를 검증할 때는 숫자가 맞는지만 확인할 것이 아니라,

> **이 결과가 내가 답하려던 질문에 대한 답인가?**

를 확인해야 한다.

</details>

---

## 3. 실제 데이터를 몇 개 확인해봐도 결과가 맞는가?

<details>
<summary>⋯</summary>

집계된 결과만 확인하는 것보다  
**일부 결과를 원본 데이터까지 거슬러 올라가 직접 확인하는 방법**도 있다.

예를 들어 고객 `101`의 결과를 확인해보자.

집계 결과에서는 다음과 같다.

| customer_id | total_amount |
|---:|---:|
| 101 | 22000 |

원본 데이터에서 고객 `101`의 주문을 확인하면 다음과 같다.

| order_id | customer_id | amount |
|---:|---:|---:|
| 1 | 101 | 10000 |
| 3 | 101 | 12000 |

두 주문을 직접 더하면 `22000`이다.

### SQL

```sql
SELECT
    *
FROM orders
WHERE customer_id = 101;
```

### pandas

```python
orders[
    orders["customer_id"] == 101
]
```

이처럼 결과 중 일부를 선택해서 **원본 데이터와 직접 대조**할 수 있다.

모든 결과를 하나씩 확인할 필요는 없지만,  
복잡한 계산을 거친 결과라면 몇 가지 사례를 직접 확인하는 것만으로도 예상하지 못한 계산 오류를 발견하는 데 도움이 된다.

</details>

## 정리

<details open>
<summary>⋯</summary>

분석 결과를 확인할 때는 단순히 코드가 정상적으로 실행되었는지만 보는 것으로 충분하지 않다.

결과를 사용하기 전에 다음을 확인할 수 있다.

| 확인할 것 | 확인 방법 |
|---|---|
| 계산한 값이 원본과 맞는가? | 계산 전후의 값 대조 |
| 질문에 맞는 값을 계산했는가? | 계산의 의미 확인 |
| 실제 데이터에서도 결과가 맞는가? | 원본 데이터와 일부 결과 직접 비교 |

결국 중요한 것은

> **계산할 수 있는가가 아니라, 계산한 결과를 믿을 수 있는가이다.**

SQL과 pandas는 데이터를 다루고 계산하기 위한 도구다.

하지만 도구가 만들어낸 결과가 분석 목적에 맞는지,  
데이터를 제대로 반영하고 있는지는 마지막까지 직접 확인해야 한다.

</details>

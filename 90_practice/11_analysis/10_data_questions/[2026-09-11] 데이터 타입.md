# 이 값들을 지금 형태 그대로 써도 괜찮을까요?

데이터를 확인하고 필요한 데이터를 골라냈다고 해서 바로 분석할 수 있는 것은 아니다.

숫자처럼 보이지만 실제로는 문자열일 수도 있고, 하나의 값에 여러 정보가 섞여 있을 수도 있다.  
이런 상태로 데이터를 사용하면 계산이나 비교가 의도한 대로 이루어지지 않을 수 있다.

---

## 질문

> 이 값을 지금 상태 그대로 사용해도 괜찮을까?

- 이 값의 데이터 타입이 정말 적절할까?
- 하나의 컬럼에 여러 의미가 섞여 있지는 않을까?
- 분석하기 좋은 형태로 바꿔야 하는 값은 없을까?

---

## 데이터

| customer_id | amount | phone |
|---:|---|---|
| 101 | 10000 | 010-1234-5678 |
| 102 | 15000 | 010-2345-6789 |
| 103 | 8000 | 010-3456-7890 |

---

## 1. 이 값의 데이터 타입이 정말 적절할까?

<details>
<summary>⋯</summary>

`amount`는 숫자처럼 보이지만 실제 데이터에서는 문자열로 저장되어 있을 수도 있다.

문자열이라면 숫자를 더하거나 평균을 계산할 때 문제가 발생할 수 있다.

### SQL

```sql
SELECT
    amount,
    typeof(amount)
FROM orders;
```

### pandas

```python
orders["amount"].dtype
```

데이터의 겉모습만 보고 타입을 판단하기보다 **실제로 어떤 타입으로 저장되어 있는지** 확인해야 한다.

</details>

---

## 2. 하나의 컬럼에 여러 의미가 섞여 있지는 않을까?

<details>
<summary>⋯</summary>

`phone`처럼 하나의 값 안에 여러 요소가 포함되어 있는 경우도 있다.

예를 들어 `010-1234-5678`은 하나의 문자열이지만, 실제로는 지역번호와 나머지 번호처럼 여러 부분으로 나눌 수 있다.

분석 목적에 따라 이런 값을 그대로 사용하는 것이 적절할 수도 있고, 여러 컬럼으로 나누는 것이 더 적절할 수도 있다.

### SQL

```sql
SELECT
    phone,
    SUBSTRING(phone, 1, 3) AS prefix
FROM customers;
```

### pandas

```python
customers["prefix"] = customers["phone"].str[:3]
```

중요한 것은 **값을 무조건 쪼개는 것이 아니라, 분석 목적에 필요한 형태인지 판단하는 것**이다.

</details>

---

## 3. 분석하기 좋은 형태로 바꿔야 하는 값은 없을까?

<details>
<summary>⋯</summary>

같은 데이터를 사용하더라도 어떤 형태로 표현하느냐에 따라 분석하기 쉬워질 수 있다.

예를 들어 금액에 `원`, 날짜에 특정 문자열이 붙어 있다면 계산이나 날짜 연산 전에 적절한 타입으로 변환해야 한다.

### SQL

```sql
SELECT
    CAST(amount AS INTEGER) AS amount
FROM orders;
```

### pandas

```python
orders["amount"] = orders["amount"].astype("int64")
```

이처럼 데이터의 형태를 확인하고 필요하다면 **분석 목적에 맞는 형태로 변환한 뒤 사용해야 한다.**

</details>

---

## 정리

<details open>
<summary>⋯</summary>

데이터를 분석하기 전에 값의 **내용뿐만 아니라 형태**도 확인해야 한다.

**데이터 타입 → 값의 구조 → 분석에 적합한 형태**

를 살펴보자.

| 작업 | SQL | pandas |
|---|---|---|
| 데이터 타입 확인 | `typeof()` | `dtype` |
| 문자열 일부 추출 | `SUBSTRING()` | `.str[]` |
| 데이터 타입 변환 | `CAST()` | `astype()` |

데이터가 이상해 보이지 않는다고 해서 바로 사용할 수 있는 것은 아니다.

**숫자는 숫자로, 날짜는 날짜로, 필요한 정보는 분석하기 좋은 형태로** 만들어져 있는지 확인해야 한다.

</details>
